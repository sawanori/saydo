# SAYDO 課金設計（後付け実装用の方針）

- 作成日: 2026-09-04 / 判定: Fable 5.1
- 前提: サーバーなし・アカウントなし。課金は StoreKit 2（端末と Apple ID で完結。レシート検証サーバーを持たない）。広告は「責めない・静かな相棒」と両立しないため採用しない。

## 1. 結論

- **フリーミアム + 自動更新サブスクリプション（SAYDO Plus）**。買い切り（Lifetime）も併売する。
- **コアループは無料のまま**にする: 朝・昼・夜のセッション、本人の声の再生、直近 14 日の Voice Timeline、週次の基本インサイト。理由: 継続率がこの製品の最大リスクであり、「朝の自分の声で動けた」初回体験の前に壁を置くと、そこで離脱する。
- AI（Foundation Models）はオンデバイスで限界費用ゼロなので、**AI を課金理由にしない**。課金理由は「記録の蓄積と理解」に置く。

## 2. 価格（日本の App Store）

| プラン | 価格 | 備考 |
|---|---|---|
| 月額 | ¥480 | 導入オファー無し |
| 年額 | ¥3,200（月あたり約 ¥267） | 7 日間の無料トライアル付き（年額のみ） |
| 買い切り（Lifetime） | ¥7,800 | 「サブスクは嫌」層の受け皿。年額の約 2.4 年分 |

根拠: サーバー費がゼロで固定費が小さいため、価格を低めに置いて転換率を優先する。国内の習慣化・日記系アプリの月額帯（¥400〜¥800）の下限寄り。8 週間の実測で D14 継続ユーザーの転換率が 3% 未満なら価格ではなく課金ポイントを見直す。

## 3. 無料と Plus の境界

| 機能 | 無料 | Plus |
|---|---|---|
| 朝・昼・夜のセッション、本人の声の再生、「今日は休む」 | ○ | ○ |
| Voice Timeline | 直近 14 日 | 全期間 + 月別ふり返り |
| インサイト | 3 件目の 1 行 + 週次の基本（上位 3 分野・理由の割合） | 週次の詳細（上位 5・傾向の変化・振り返り文）、月次パターン |
| データの書き出し（音声 + JSON） | × | ○ |
| 「初めて動けた日」カード（R10） | 1 枚目のみ | 全て |
| 本人の声を通知音にする（task_021） | × | ○ |
| 逃げたいことを 1 日に 2 件以上扱う（v2） | × | ○ |

境界の原則: 「今日動くために必要なもの」は無料、「自分の逃げ方を長期で理解するもの」は有料。

## 4. 課金の見せ方（ペイウォールの時期）

- オンボーディングでは出さない。初回の権限 2 つと時刻設定だけで終える。
- 出すタイミングは次の 2 つだけ: (a) 初めて `outcome == done` になった夜（「今日の前進を残せた」直後に、静かに 1 画面）、(b) 15 日目に Timeline の 15 日以前が畳まれた時。
- ペイウォールの文言も Guardrails を通す。「あと N 日で消えます」「今だけ」などの圧をかけない。閉じるボタンは常に 1 タップ。
- 再表示は 14 日に 1 回まで。

## 5. 実装（Phase 3 に task_022 として追加する内容）

- StoreKit 2: `Product.products(for:)`、`Transaction.currentEntitlements`、`AppStore.sync()` による復元。サーバー検証は行わない（端末内でトランザクションを検証）。
- エンタイトルメント判定は `EntitlementStore`（@Observable）1 か所に集約し、UI は `isPlus` だけを見る。
- StoreKit Configuration ファイル（`Saydo.storekit`）でローカルテスト。TestFlight ではサンドボックスで年額トライアルの流れを確認。
- App Review 要件: ペイウォールに価格・期間・自動更新の明記、利用規約と プライバシーポリシーの URL、復元ボタン。
- 受け入れチェック追加: 無料状態で朝・昼・夜が完走する / Plus 購入後に 15 日以前の Timeline が開く / 復元が動く / ペイウォール文言が Guardrails を通る。

## 6. やらないこと

- 広告、ポイント、ストリーク解除課金、通知回数の課金、AI 回数の課金（いずれも「責めない」「静か」と衝突する）。
- 家族共有と法人向けは v2 以降。
